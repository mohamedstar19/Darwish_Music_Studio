# Darwish Music Studio
## وثيقة الرؤية والمميزات والخطة التقنية

**الإصدار:** 1.0  
**تاريخ الإعداد:** 21 أكتوبر 2026  
**الحالة:** وثيقة تأسيسية للمشروع — بعض القرارات التجارية والتشغيلية ما زالت تحتاج إلى اعتماد.

---

## 1. الملخص التنفيذي

**Darwish Music Studio** منصة موسيقية عربية تركز على أغاني الطفولة وشارات الكرتون والأنمي والموسيقى المرتبطة بذكريات جيل التسعينات والألفينات، مع إمكانية التوسع إلى أعمال موسيقية أصلية ومحتوى مرخّص.

الهدف هو بناء تجربة متكاملة عبر الويب والموبايل، تجمع بين مكتبة موسيقية حسب الطلب، ومحطات راديو تعمل وفق جداول بث، ومشغل حديث، وقوائم تشغيل شخصية، ولوحة إدارة للمحتوى.

**الشعار المقترح:**  
«ذكريات عايشة جوانا... وأغاني عمرها ما بتنسينا»

**الشعار الإنجليزي المقترح:**  
“Your Memories. Your Music. Your Universe.”

### مبادئ المشروع

- تجربة عربية سهلة وسريعة، مع دعم التصميم المتجاوب.
- بناء تقني قابل للتوسع بدل تعقيد النسخة الأولى دون داعٍ.
- إعطاء الأولوية لاستقرار تشغيل الصوت وتجربة المستخدم.
- بناء مكتبة قانونية من الأعمال الأصلية أو المحتوى المرخّص.
- فصل تخزين الوسائط وتقديمها عن منطق التطبيق عند الحاجة.
- تطوير واجهات API تسمح بربط تطبيق Flutter مستقبلًا.

---

## 2. الجمهور المستهدف

1. محبو شارات الكرتون والأنمي المدبلجة بالعربية.
2. جيل التسعينات والألفينات الباحث عن موسيقى الطفولة والذكريات.
3. المستمعون الذين يفضّلون المحطات الإذاعية ذات التصنيفات الواضحة.
4. الفنانون والمنتجون الذين يرغبون في نشر أعمال أصلية، وفق اتفاقات واضحة.

## 3. المميزات الأساسية

### 3.1 مكتبة الموسيقى حسب الطلب (On-Demand)

- تصفح الأغاني حسب التصنيف والعمل والألبوم والفنان.
- البحث باسم الأغنية أو الفنان أو العمل.
- صفحات تفاصيل للأغاني مع البيانات المتاحة والمصرح بنشرها.
- إضافة الأغاني إلى المفضلة.
- عرض آخر ما تم الاستماع إليه.
- متابعة حالة الملف الصوتي وسلامته من لوحة الإدارة.

### 3.2 محطات الراديو (Radio Mode)

محطات مقترحة قابلة للتغيير حسب توفر المحتوى والحقوق:

- Spacetoon Memories
- Cartoon Arabic
- 90s & 2000s
- Anime Arabic
- Kids Classics
- Drama Memories
- Darwish Originals

المميزات المقترحة:

- بث مجدول أو مستمر وفق إعداد المحطة.
- عرض اسم الأغنية الحالية وصورة الغلاف عند توفرها.
- قائمة بالأغاني السابقة والقادمة إن كان جدول البث يسمح بذلك.
- استقبال طلبات الأغاني من المستخدمين.
- التصويت للأغاني في المحطات التفاعلية.
- صفحة مستقلة لكل محطة.

> يجب الحصول على التراخيص اللازمة قبل بث أي محتوى محمي بحقوق النشر.

### 3.3 مشغل الموسيقى

- تشغيل وإيقاف وتقديم وتأخير.
- الانتقال إلى الأغنية السابقة أو التالية.
- شريط تقدم الصوت والتحكم في مستوى الصوت.
- إضافة إلى المفضلة وقوائم التشغيل.
- استمرار المشغل أثناء التنقل بين صفحات الموقع.
- تصميم متجاوب للموبايل والكمبيوتر.
- دعم مفاتيح التحكم وشاشة القفل في تطبيق الموبايل بحسب النظام وإمكاناته.
- رسائل واضحة عند انقطاع الاتصال أو تعذر تشغيل ملف.

### 3.4 حسابات المستخدمين

- إنشاء الحساب وتسجيل الدخول واستعادة الوصول.
- الملف الشخصي.
- المفضلة.
- سجل الاستماع.
- قوائم التشغيل الخاصة.
- إعدادات الحساب والخصوصية.

### 3.5 قوائم التشغيل (Playlists)

- إنشاء قوائم شخصية وتعديلها وحذفها.
- إعادة ترتيب الأغاني.
- مشاركة القوائم عند السماح بذلك.
- قوائم رسمية يديرها فريق المنصة.
- قوائم جاهزة حسب المزاج أو الفترة الزمنية أو نوع المحتوى.

## 4. أفكار تميّز المنصة

### 4.1 «عيش ذكرياتك من جديد»

قسم يعرض قوائم تشغيل مختارة حسب نوع الذكريات، مثل المغامرات والأغاني الهادئة وشارات الطفولة. ينبغي أن تعتمد الاقتراحات على المحتوى المتوفر والمرخّص فقط.

### 4.2 My Music Memories

ملخص شخصي يعرض، عند تفعيل سجل الاستماع:

- عدد الأغاني التي استمع إليها المستخدم.
- الوقت التقريبي للاستماع.
- أكثر التصنيفات والمحطات استخدامًا.
- الأغاني المفضلة خلال فترة معينة.

ينبغي توفير إعدادات واضحة للخصوصية وإمكانية تعطيل سجل الاستماع أو حذفه.

### 4.3 زر «فاجئني بأغنية»

يشغّل محتوى عشوائيًا من المكتبة المسموح بها، مع إمكانية تقييد الاختيار حسب تصنيف أو محطة.

### 4.4 Retro Mode

مظهر اختياري مستوحى من أجهزة الراديو ومشغلات الموسيقى القديمة، مع الحفاظ على سهولة الاستخدام وإمكانية الوصول.

### 4.5 Sleep Timer

إيقاف التشغيل تلقائيًا بعد مدة يحددها المستخدم، خصوصًا في تطبيق الموبايل.

### 4.6 وضع السيارة

واجهة تشغيل مبسطة بأزرار كبيرة ومعلومات محدودة لتقليل التشتيت. يجب عدم تشجيع التفاعل اليدوي أثناء القيادة.

### 4.7 Darwish Originals

قسم للأعمال الأصلية التي تملك المنصة حقوق استخدامها، مثل المقطوعات الخلفية والموسيقى الهادئة وشارات الشخصيات والقصص الجديدة. يمكن التعاون مع فنانين ومنتجين بعقود واضحة.

### 4.8 Lyrics & Credits

عرض بيانات الأغنية واعتماداتها، وإظهار الكلمات المتزامنة عند توفر الحقوق اللازمة. امتلاك تسجيل صوتي لا يعني تلقائيًا امتلاك حقوق نشر الكلمات أو التأليف.

### 4.9 مساعد موسيقي ذكي — مرحلة مستقبلية

يسمح للمستخدم بوصف ما يريد سماعه باللغة العربية، ثم يقترح قوائم مناسبة. يمكن البدء بالبحث النصي والتصنيفات وقواعد توصية بسيطة قبل استخدام نماذج ذكاء اصطناعي متقدمة.

### 4.10 غرف الاستماع والميزات الاجتماعية — مرحلة مستقبلية

- قوائم تشغيل مشتركة.
- مشاركة روابط الأغاني.
- غرف استماع متزامنة.
- تصويت على محتوى محطات تفاعلية.

هذه المميزات ليست ضمن الحد الأدنى للإطلاق؛ لأنها تزيد متطلبات التزامن والإشراف والأمان.

### 4.11 الاستماع دون اتصال

يمكن إضافة تنزيلات داخل التطبيق عندما تسمح حقوق المحتوى بذلك. أما تجربة الويب دون اتصال فتحتاج إلى دراسة منفصلة حسب المتصفح وحدود التخزين وسياسة الحقوق.

### 4.12 تطبيق ويب تقدمي (PWA)

يمكن توفير تجربة قابلة للتثبيت على الأجهزة المتوافقة قبل إصدار تطبيقات الموبايل الكاملة. يجب اختبار حدود التشغيل في الخلفية على كل متصفح ونظام مستهدف.

## 7. البنية التقنية المقترحة

هذه بنية أولية قابلة للمراجعة قبل التنفيذ الفعلي.

| المكوّن | التقنية المقترحة | الاستخدام |
|---|---|---|
| Web Frontend | React + TypeScript + Vite | واجهة الويب |
| Backend API | Laravel | الحسابات والمكتبة والصلاحيات ولوحة الإدارة |
| Database | PostgreSQL | المستخدمون والأغاني والقوائم وسجلات التشغيل |
| Cache / Queues | Redis عند الحاجة | التخزين المؤقت والمهام الخلفية |
| Media Storage | TrueNAS للتطوير أو الأرشفة، أو تخزين كائني مناسب للإنتاج | حفظ ملفات الوسائط |
| Media Delivery | Nginx أو خدمة تخزين متوافقة مع S3 و/أو CDN | تقديم ملفات الصوت |
| Radio Streaming | Icecast أو حل بث مناسب | محطات الراديو |
| Mobile App | Flutter | تطبيق Android وiOS |
| Reverse Proxy | Traefik | توجيه الاتصالات وTLS ضمن البنية الحالية |
| Deployment | Docker Compose | تشغيل الخدمات ونشرها |
| Monitoring | سجلات ومراقبة موارد وخدمات مناسبة | اكتشاف الأعطال ومتابعة الأداء |

### قرارات هندسية مبدئية

- PostgreSQL كقاعدة بيانات أساسية؛ لا حاجة إلى MongoDB في النسخة الأولى دون سبب محدد.
- فصل بيانات التطبيق عن ملفات الصوت.
- استخدام واجهات API موثقة وقابلة للإصدار (versioning) لتسهيل تطبيق Flutter.
- تنفيذ مهام معالجة الوسائط في الخلفية عند الحاجة.
- عدم تعريض قواعد البيانات أو منافذ الخدمات الداخلية للإنترنت مباشرة.
- استخدام أسرار البيئة أو نظام أسرار مناسب بدل وضع كلمات المرور داخل المستودع.
- تحديد سياسة للنسخ الاحتياطي والاستعادة واختبارها.

### التشغيل حسب الطلب مقابل الراديو

**الاستماع حسب الطلب:** يمكن تقديم الملفات عبر HTTP مع دعم Range Requests، بما يسمح بالانتقال إلى مواضع مختلفة في الملف عند دعم الخادم والمتصفح لذلك.

**الراديو:** يمكن استخدام Icecast للبث المستمر، أو HLS عند وجود حاجة محددة للتوافق أو توزيع البث. لا يلزم استخدام HLS لكل ملف موسيقي.

## 8. التخزين والتكلفة والأداء

تكلفة نقل الصوت قد تصبح أعلى من تكلفة تشغيل التطبيق نفسه.

مثال تقريبي: بث بمعدل 128 كيلوبت/ثانية لمدة ساعة إلى 1,000 مستمع يستهلك نظريًا نحو **57.6 جيجابايت** من البيانات الإجمالية، قبل احتساب فروق البروتوكول وإعادة الإرسال والتخزين المؤقت.

### توصيات

- استخدام HomeLab للتطوير والاختبار في البداية.
- عدم جعل اتصال الإنترنت المنزلي نقطة التوزيع العامة الوحيدة عند الإطلاق.
- تقييم سرعة الرفع، والتوافر، واستهلاك البيانات، والحماية قبل اختيار الاستضافة.
- استخدام CDN أو خدمة توزيع مناسبة عندما يبرر عدد المستخدمين ذلك.
- مراقبة استهلاك النطاق الترددي والتكلفة.
- إنشاء نسخ احتياطية منفصلة واختبار الاستعادة.
- استخدام روابط وصول محدودة أو آليات حماية مناسبة للملفات الخاصة بالمشتركين إذا ظهرت هذه الحاجة.
- ضبط جودة الصوت بناءً على احتياجات المستخدمين والتكلفة والحقوق.

## 9. الحقوق والامتثال

قبل نشر أي محتوى، يجب تحديد حقوق الاستخدام ذات الصلة. وقد تشمل حقوق التأليف والتلحين والكلمات والتسجيل الصوتي والأداء والتوزيع، بحسب العمل والبلد وطريقة الاستخدام.

### تصنيف مقترح للمحتوى

1. أعمال أصلية تملك المنصة حقوقها.
2. أعمال حصلت المنصة على ترخيص مناسب لها.
3. أعمال لم تُحسم حقوقها بعد، وتظل غير منشورة حتى استكمال الموافقات.

### متطلبات تشغيلية

- تسجيل مصدر كل عمل ومستندات الترخيص ذات الصلة.
- تسجيل نطاق الترخيص: البث، والاستماع حسب الطلب، والتنزيل، والاستخدام التجاري، والمناطق الجغرافية، ومدة الترخيص.
- مراجعة التراخيص قبل تفعيل المحتوى.
- توفير وسيلة واضحة للإبلاغ عن حقوق المحتوى.
- إيقاف المحتوى عند انتهاء الترخيص أو وجود مطالبة تستدعي المراجعة.
- إعداد شروط الاستخدام وسياسة الخصوصية وفق متطلبات السوق المستهدف.

لا يُفترض أن توفر أغنية على الإنترنت أو امتلاك ملف صوتي يمنح حق إعادة نشره أو بثه.

## 10. نموذج الإيرادات

يوصى بالتركيز على جودة التجربة والتحقق من الطلب قبل بناء نظام اشتراكات معقد.

خيارات مستقبلية:

- خطة مجانية لمحتوى يسمح ترخيصه بذلك.
- اشتراك Premium لمزايا إضافية، بشرط أن تسمح الحقوق بالنموذج التجاري.
- توزيع وترخيص Darwish Originals.
- شراكات مع فنانين ومنتجين.
- محطات برعاية تجارية وفق اتفاقات مناسبة.
- منتجات مرتبطة بالهوية الأصلية للمشروع.

يجب ألا تُفعّل الإعلانات أو الاشتراكات أو أي توزيع تجاري إلا بما يتفق مع حقوق المحتوى والاتفاقات المعمول بها.

## 11. خارطة الطريق

### المرحلة 0 — تحديد المتطلبات

- تحديد الجمهور والسوق المستهدف.
- حسم نموذج الإطلاق المجاني أو المدفوع.
- تحديد ما إذا كان الإطلاق الأول على HomeLab أو على استضافة سحابية.
- تحديد مصدر المكتبة والحقوق المتاحة.
- اعتماد الهوية البصرية وتجربة الاستخدام.

**المخرج:** وثيقة متطلبات معتمدة ونطاق واضح للنسخة الأولى.

### المرحلة 1 — التصميم والبنية الأساسية

- تصميم الواجهات المتجاوبة.
- إعداد مستودع المشروع وبيئة التطوير.
- إعداد Docker Compose للخدمات المطلوبة.
- إعداد PostgreSQL وLaravel.
- إعداد المصادقة والصلاحيات الأساسية.
- إعداد الاختبارات الأولية.

**المخرج:** أساس تقني يعمل ويمكن تطويره بأمان.

### المرحلة 2 — المكتبة والمشغل

- بناء نموذج بيانات الأغاني والتصنيفات والألبومات.
- إنشاء واجهات API.
- تطوير البحث والتصفح.
- بناء المشغل المستمر.
- إضافة المفضلة وقوائم التشغيل الأساسية.
- اختبار التشغيل على أجهزة ومتصفحات مختلفة.

**المخرج:** نسخة ويب أولية قابلة للاستخدام مع محتوى تجريبي مرخّص.

### المرحلة 3 — لوحة الإدارة

- رفع الملفات وإدارة بياناتها.
- إدارة الحقوق وحالة النشر.
- إدارة التصنيفات والقوائم الرسمية.
- تسجيل الأخطاء ومراقبة مهام المعالجة.

**المخرج:** إدارة المكتبة دون تعديل قاعدة البيانات يدويًا.

### المرحلة 4 — الراديو

- اختيار محرك البث.
- بناء جدول تشغيل المحطات.
- ربط حالة البث بواجهة الموقع.
- اختبار الاستمرارية وإعادة الاتصال.
- قياس استهلاك النطاق الترددي.

**المخرج:** محطات بث تجريبية مستقرة للمحتوى المسموح به.

### المرحلة 5 — الاختبار والإطلاق التجريبي

- اختبارات وظيفية وأمنية.
- اختبار الضغط والاتصالات المتزامنة.
- اختبار انقطاع الشبكة واستعادة التشغيل.
- مراجعة الخصوصية والحقوق.
- إعداد النسخ الاحتياطي والاستعادة.
- نشر نسخة تجريبية ومراقبة الأخطاء.

**المخرج:** نسخة Beta قابلة للتقييم.

### المرحلة 6 — تطبيق الموبايل

- إعادة استخدام واجهات API.
- تطوير تطبيق Flutter.
- دعم التشغيل في الخلفية والتحكم من شاشة القفل بحسب النظام.
- اختبار استهلاك البطارية والبيانات.
- دراسة التنزيل دون اتصال إذا سمحت الحقوق.

### المرحلة 7 — ميزات متقدمة

- إحصائيات ذكريات المستخدم.
- توصيات موسيقية.
- مساعد بحث ذكي.
- PWA محسّن.
- قوائم مشتركة وغرف استماع.
- نموذج اشتراك عند ثبوت الحاجة وتوافر الحقوق.

## 12. نطاق النسخة الأولى (MVP)

لتجنب تضخم النطاق، يجب أن تحتوي النسخة الأولى على:

- موقع متجاوب باللغة العربية.
- واجهة رئيسية ومكتبة موسيقية.
- بحث وتصنيفات.
- مشغل موسيقى مستمر أثناء التنقل.
- صفحات تفاصيل للأغاني.
- حسابات مستخدمين.
- المفضلة وقوائم تشغيل أساسية.
- لوحة إدارة لإضافة المحتوى وتنظيمه.
- إدارة معلومات الحقوق وحالة النشر.
- أساس API مناسب لتطبيق موبايل لاحقًا.
- سجلات تشغيل وأخطاء أساسية.

يمكن تأجيل الراديو إلى إصدار لاحق إذا أدى إدخاله مبكرًا إلى تأخير إطلاق المكتبة والمشغل. وإذا كان الراديو هو القيمة الأساسية للمشروع، فيمكن جعله جزءًا من MVP بشرط توفر المحتوى المرخّص والبنية المناسبة.

## 15. قرارات مطلوبة قبل التنفيذ

يجب حسم الأسئلة التالية قبل تثبيت المعمارية وخطة التنفيذ:

1. **نموذج العمل:** هل الإطلاق مجاني بالكامل، أم مجاني مع إمكانية اشتراكات مستقبلية؟
2. **الاستضافة:** هل نبدأ بـ HomeLab للتطوير والاختبار فقط، أم نحتاج إلى بيئة سحابية منذ البداية؟
3. **المحتوى:** هل تتوفر أعمال أصلية أو تراخيص جاهزة، أم يجب أن تكون النسخة التجريبية بمواد أصلية فقط؟
4. **نطاق الإطلاق:** هل الراديو شرط أساسي في أول نسخة، أم يمكن إطلاق المكتبة والمشغل أولًا؟
5. **المنصات:** هل نبدأ بالويب وPWA، ثم نطور Flutter بعد استقرار الـ API؟
6. **اللغة:** هل تكون العربية هي اللغة الأساسية مع دعم الإنجليزية لاحقًا؟

## 16. التوصية النهائية

التوصية هي بناء **Darwish Music Studio V1** كمنصة ويب متجاوبة ذات مكتبة ومشغل ولوحة إدارة، مع قاعدة بيانات PostgreSQL وBackend باستخدام Laravel وواجهة React، وتصميم API قابل لإعادة الاستخدام في Flutter.

يُستخدم HomeLab في التطوير والاختبار عند ملاءمته، بينما يُتخذ قرار الاستضافة العامة بعد قياس استهلاك البيانات ومتطلبات التوافر. ويجب أن تكون حقوق المحتوى جزءًا من نموذج البيانات وسير العمل الإداري منذ البداية، لا خطوة مؤجلة إلى ما بعد الإطلاق.

**الخطوة التالية:** اعتماد القرارات الستة في القسم السابق، ثم إعداد مخطط قاعدة البيانات، وهيكل المشروع، وعقود API، وخطة تنفيذ مقسمة إلى مهام قابلة للاختبار.
